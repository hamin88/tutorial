## Comprehensive Java & OOPs Concepts Documentation## 1. JDK vs. JRE vs. JVM

* JDK (Java Development Kit): The full software development package used to write and compile Java applications. It physically exists on your drive and includes development utilities like javac alongside the JRE.
* JRE (Java Runtime Environment): An installation package meant for end-users to execute Java applications. It bundles the standard Java class libraries with the JVM. It has no development tools.
* JVM (Java Virtual Machine): An abstract computing machine created in memory when execution begins. It reads compiled .class bytecode and translates it into native hardware instructions.

## Relationship Formulas

* JDK = JRE + Development Tools (javac, jdb, jar, etc.)
* JRE = JVM + Standard Class Libraries

## Summary Table

| Feature | JDK | JRE | JVM |
|---|---|---|---|
| Primary Audience | Software Developers | End Users / Deployments | The Host Operating System |
| Core Function | Writing and compiling code | Launching & running applications | Executing compiled bytecode |

## 2. Core Object-Oriented Programming (OOPs) Concepts
The four foundational pillars of OOPs are:

* Encapsulation: Wrapping data (variables) and code (methods) together into a single class unit. It restricts direct access by using private variables and exposing them via public getters and setters.
* Inheritance: The mechanism where a child class acquires the properties and behaviors of a parent class to maximize code reusability.
* Polymorphism: The ability for a single action or method name to behave differently based on context. It occurs as compile-time (overloading) or runtime (overriding).
* Abstraction: Hiding complex inner implementation details and showing only essential features to the user via interfaces or abstract classes.

## 3. Comparison: == Operator vs. equals() Method

* == Operator: A binary operator that compares raw data. For primitives, it checks if values match. For objects, it checks if both variables point to the exact same memory address (reference).
* equals() Method: A method inherited from the Object class used to compare logical content. Classes like String and Integer override it to look inside the object instead of checking memory addresses.

## Java Example

String str1 = new String("Hello");
String str2 = new String("Hello");

System.out.println(str1 == str2);      // false (Different memory addresses)
System.out.println(str1.equals(str2)); // true  (Same textual content)

## 4. Method Overloading vs. Method Overriding

* Method Overloading: Multiple methods within the same class share a name but have different parameter lists (count, type, or order). It is resolved at compile-time (Static binding).
* Method Overriding: A child class redefines a method it inherited from its parent class using the exact same signature and return type. It is resolved at runtime (Dynamic binding).

## Java Example

// Overloading (Same class, different parameters)class Calculator {
    int add(int a, int b) { return a + b; }
    int add(int a, int b, int c) { return a + b + c; }
}
// Overriding (Parent and Child classes, same parameters)class Animal { void sound() { System.out.println("Animal sound"); } }class Dog extends Animal { @Override void sound() { System.out.println("Bark"); } }

## 5. ArrayList vs. LinkedList

* ArrayList: Backed by a dynamically resizing array stored in contiguous memory. It supports instant index-based random access but requires expensive element shifting during insertions or deletions in the middle.
* LinkedList: Backed by a doubly linked chain of nodes scattered in memory. Finding elements requires traversing the list sequentially, but inserting or deleting elements only requires changing pointer references.

## Performance Index

* Random Access: ArrayList takes $O(1)$ constant time; LinkedList takes $O(n)$ linear time.
* Middle Modifications: ArrayList takes $O(n)$ time (shifting items); LinkedList takes $O(1)$ time once the node is reached.

## 6. The Purpose of hashCode()
The hashCode() method generates an integer representation of an object to enable high-speed lookups in hash-based data structures like HashMap and HashSet.
## Key Rules & The Contract

* It converts $O(n)$ linear search times into near-instant $O(1)$ constant lookup times.
* The Contract: If obj1.equals(obj2) is true, then obj1.hashCode() must return the exact same integer value.
* Two unequal objects can share the same hash code, an occurrence known as a hash collision.

## 7. HashMap vs. ConcurrentHashMap

* HashMap: Non-thread-safe collection designed for single-threaded environments. It uses zero synchronization to prioritize speed and accepts one null key and multiple null values.
* ConcurrentHashMap: Fully thread-safe collection built for multi-threaded applications. It uses fine-grained, bucket-level locking so threads can write to different segments of the map simultaneously. It strictly prohibits null keys and values.

## 9. Checked vs. Unchecked Exceptions

* Checked Exceptions: Exceptional conditions that an application must anticipate and handle (e.g., missing files). The compiler scans for these at compile-time and blocks compilation unless they are explicitly handled using a try-catch block or a throws clause. They inherit from Exception.
* Unchecked Exceptions: Programming mistakes or runtime failures (e.g., dividing by zero, null pointer access). The compiler ignores them during build time. They inherit directly from RuntimeException.

------------------------------
## 10. Understanding Immutability
Immutability dictates that an object's internal data state cannot be altered after it is created. Modifying an immutable object results in the system generating a brand-new object with the updated values while leaving the original unchanged.
## Design Principles for Custom Immutable Classes

   1. Declare the entire class as final so it cannot be extended or overridden.
   2. Mark all internal variables as private and final.
   3. Provide no setter methods.
   4. Perform deep copying on any mutable fields inside constructors and getters to block external data manipulation.
